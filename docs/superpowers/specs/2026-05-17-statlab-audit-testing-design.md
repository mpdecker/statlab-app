## 2. Audit Findings & Fixes

### Critical — silently wrong p-values

| File | Bug | Fix |
|------|-----|-----|
| `distributions.js:chiPVal` | Wilson-Hilferty cube-root approximation produces ~.07 for χ²(1)=3.84 (should be .05) | Add a `lowerIncGamma(a, x)` helper using a series expansion for `x < a+1` and a continued fraction otherwise (reuses existing `lngamma`). Then `chiPVal(chi2, df) = 1 - lowerIncGamma(df/2, chi2/2)`. Validate against R's `pchisq`. |
| `distributions.js:tInv2` | Binary search ceiling of 20 — returns 20 for extreme t-values (e.g. `tInv2(.001, 1000)` should be ~3.3 but if the p-value function maps t=20 to near 0, the binary search will still converge correctly for that case; the real issue is high-df + small alpha where the critical value exceeds 20) | Extend ceiling to 100; for df > 1000 short-circuit to `normalINV(1 - alpha/2)` |
| `distributions.js:normalCDF` | Horner polynomial approximation has ~1e-7 max error; degrades in tails beyond z=3.5 | Replace with Hart (1968) rational approximation accurate to 1e-15 |

### Medium — incorrect results in edge cases

| File | Bug | Fix |
|------|-----|-----|
| `tests/means.js:yuentTest` | If both groups are constant after winsorizing, `se=0` → `t=NaN` returned silently | Return `null` when `se < 1e-14` |
| `math/matrix.js:matInv` | No singularity check — rank-deficient matrix produces `NaN` silently | Compute determinant; return `null` if `|det| < 1e-14` |
| `tests/categorical.js` (Fisher's exact) | Loops over all `k` — can hang for cell counts > 500 | Add guard: return `null` with `{ warning: "n too large for exact test" }` when total n > 500 |

### Low — dead code / approximation quality

| File | Issue | Fix |
|------|-------|-----|
| `core.js:fmtP` | Middle branch `p < .01` produces identical output to final branch — dead code | Collapse to two branches: `p < .001` → `"p < .001"`, else → `p.toFixed(3)` |
| `distributions.js:shapiroWilk` | Uses `normalINV` for Blom scores without published Royston a-coefficients — biased for n < 10 | Add `approximate: true` flag in return object when n < 10 |

## 3. Test Architecture

### Reference fixture strategy

`src/tests/__fixtures__/reference.json` is generated by running the same inputs through R (or `scipy`/`pingouin`) and committing the output as the oracle. Structure:

```json
{
  "distributions": {
    "normalCDF": [
      { "z": 0,     "expected": "FILL_FROM_R: pnorm(0)" },
      { "z": 1.96,  "expected": "FILL_FROM_R: pnorm(1.96)" },
      { "z": -3.5,  "expected": "FILL_FROM_R: pnorm(-3.5)" }
    ],
    "chiPVal": [
      { "chi2": 3.841, "df": 1, "expected": "FILL_FROM_R: pchisq(3.841, 1, lower.tail=FALSE)" },
      { "chi2": 5.991, "df": 2, "expected": "FILL_FROM_R: pchisq(5.991, 2, lower.tail=FALSE)" }
    ],
    "tPVal": [
      { "t": 2.0, "df": 10, "expected": "FILL_FROM_R: 2*pt(-abs(2.0), 10)" },
      { "t": 1.96, "df": 1000, "expected": "FILL_FROM_R: 2*pt(-abs(1.96), 1000)" }
    ]
  },
  "means": {
    "tWelch": {
      "input": { "a": [2,4,6,8], "b": [1,3,5] },
      "expected": "FILL_FROM_R: t.test(c(2,4,6,8), c(1,3,5))",
      "apa": "FILL_AFTER_R_RUN"
    }
  }
}
```

> **Note:** All `FILL_FROM_R` values must be populated by running the corresponding R expressions during Phase 2 before any test assertions are written against them.

### Assertion helpers (`src/tests/__fixtures__/helpers.js`)

```js
// Numerical tolerance check
export const approx = (actual, expected, tol = 1e-4) =>
  Math.abs(actual - expected) < tol;

// APA exact string match
export const matchAPA = (result, expectedStr) =>
  result.apa === expectedStr;
```
