# CI Pipeline Setup — Full Quality Gates

## Context

- CI workflow exists on `feat/batch9-wiring` (current branch) but **not on `main`**
- The workflow uses `pnpm` but only `package-lock.json` exists (no `pnpm-lock.yaml`)
- Library (`packages/statlab/`) has `tsconfig.json` with `checkJs: false` and `tsup` ESM+CJS build
- Library has `vitest.config.js` with 90% line coverage threshold already configured
- No eslint or prettier config exists anywhere in the project
- JSDoc parameter types were added to ~1,100 functions across prior commits

## Goals

1. **Complete pnpm migration** — generate lockfile, add `packageManager` field, remove `package-lock.json`
2. **Enhance CI workflow** — keep test+build matrix (Node 20/22), add type-check, lint, coverage, pre-publish verify
3. **Set up eslint** — minimal config for the library (`packages/statlab/`)
4. **Enable CI type-checking** — separate `tsconfig.ci.json` with `checkJs: true` + `noEmit: true`
5. **Land CI on `main`** — merge or cherry-pick the workflow + config files so CI gates future PRs

## Execution Plan

### Step 1: Pnpm migration

`pnpm` is already the CI's package manager. We need to complete the migration:

1. Run `pnpm install` from the repo root to generate `pnpm-lock.yaml`
2. Add `"packageManager": "pnpm@10.x.x"` field to root `package.json` (exact version from `pnpm --version`)
3. Remove `package-lock.json` (no longer needed)
4. Add `package-lock.json` to `.gitignore` if not already ignored
5. Verify `pnpm -r test` and `pnpm -r build` pass locally

### Step 2: ESLint setup for the library

Create `packages/statlab/eslint.config.js` with a flat config:

```js
import js from '@eslint/js';
import globals from 'globals';

export default [
  js.configs.recommended,
  {
    files: ['src/**/*.js'],
    ignores: ['src/**/*.test.js', 'src/methods/__fixtures__/**'],
    languageOptions: {
      ecmaVersion: 2022,
      sourceType: 'module',
      globals: { ...globals.node },
    },
    rules: {
      'no-unused-vars': ['error', { argsIgnorePattern: '^_', varsIgnorePattern: '^_' }],
      'no-undef': 'error',
      'no-console': 'error',
      'no-debugger': 'error',
    },
  },
];
```

1. Install devDependencies in `packages/statlab/`: `pnpm add -D eslint @eslint/js globals -w statlab`
2. Create the config file
3. Add `"lint": "eslint src/"` script to `packages/statlab/package.json`
4. Run `pnpm lint -w statlab` and fix any violations
5. Add `"lint": "eslint src/"` to root `package.json` as `pnpm -r lint`

### Step 3: Type-checking CI config

The current `tsconfig.json` uses `checkJs: false` (declaration generation only). For CI type-checking:

1. Create `packages/statlab/tsconfig.ci.json`:
```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "checkJs": true,
    "noEmit": true
  }
}
```

2. Add `"typecheck": "tsc -p tsconfig.ci.json"` to `packages/statlab/package.json`
3. Run `pnpm typecheck -w statlab` — if many errors exist, categorize them and add a plan note about fixing iteratively. Initial CI can run as `allow-failure` or with `--pretty | head` to report without blocking.

### Step 4: Enhance CI workflow

Replace the existing `.github/workflows/ci.yml` with a multi-job pipeline:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test-build:
    name: test & build (Node ${{ matrix.node }})
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        node: ['20.x', '22.x']
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: pnpm -r test
      - run: pnpm -r build

  lint:
    name: lint
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: '22.x'
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint -w statlab

  typecheck:
    name: type-check
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: '22.x'
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: pnpm typecheck -w statlab

  coverage:
    name: coverage
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: '22.x'
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: pnpm exec vitest run --coverage -w statlab

  pack-verify:
    name: npm pack verify
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: '22.x'
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: pnpm build -w statlab
      - run: pnpm pack --pack-destination /tmp -w statlab
```

### Step 5: Verify locally

1. `pnpm -r test` — all 6,023 tests pass
2. `pnpm -r build` — library tsup + app vite build pass
3. `pnpm lint -w statlab` — zero violations
4. `pnpm typecheck -w statlab` — zero errors (or documented exceptions)
5. `pnpm exec vitest run --coverage -w statlab` — meets 90% threshold
6. `pnpm pack -w statlab` — produces valid tarball

### Step 6: Land on main

1. Commit all CI config and pnpm migration changes on the current branch
2. Create a PR from `feat/batch9-wiring` → `main`
3. Verify CI passes on the PR before merging

## Key Decisions

| Decision | Choice |
|----------|--------|
| Package manager | pnpm (migrate from npm) |
| Linter | eslint with flat config, core rules only |
| Type-check scope | Library only (`packages/statlab/`), not the React app |
| Type-check strictness | `checkJs: true` with noEmit; if too many errors, start with `allow-failure` and fix incrementally |
| Coverage threshold | 90% lines (already configured in vitest.config.js) |
| ESLint scope | Library source only, excluding test files and fixtures |

## Risks

- **Type-check may produce many errors**: The JSDoc annotation commits were extensive but untested with `checkJs: true`. If the error count is high, mark the typecheck job as non-blocking initially and fix in follow-up passes.
- **Coverage may be below 90%**: The 90% threshold was set speculatively. The actual coverage may be lower, requiring threshold adjustment or additional tests.
- **pnpm lockfile generation**: Running `pnpm install` will produce a fresh lockfile. The `pnpm/action-setup@v4` version (10) must match the exact version generated. Pin the version precisely.
- **ESLint violations in 84+ source files**: The initial lint run may surface many unused-vars or other issues. Fix them all before landing the CI to avoid a red pipeline on day one.

## Validation

3. `pnpm-lock.yaml` is generated and `package-lock.json` is removed
4. `pnpm -r test` produces same 6,023-passing result with pnpm as with npm
