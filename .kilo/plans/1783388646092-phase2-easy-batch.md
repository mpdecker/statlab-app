## Implementation Plan

### Step 1: Add oracle generation to `gen-reference.py`

Add one Python section per module after the existing `experimental` section.
Each section follows the established pattern:

```python
# ── spc ────────────────────────────────────────────────────────────
# Control chart constants A2, D3, D4 from textbook tables (Montgomery).
# xbarChart: CL = mean(means), UCL/LCL = CL ± A2 * Rbar
# rChart: CL = mean(ranges), UCL/LCL = d4*CL, d3*CL
_spc_data = [10 + ((i*7+3) % 11 - 5) * 0.3 for i in range(50)]
_spc_subgroup = 5
_spc_nsg = len(_spc_data) // _spc_subgroup
_spc_means = [np.mean(_spc_data[i*_spc_subgroup:(i+1)*_spc_subgroup]) for i in range(_spc_nsg)]
_spc_ranges = [max(_spc_data[i*_spc_subgroup:(i+1)*_spc_subgroup]) - min(_spc_data[i*_spc_subgroup:(i+1)*_spc_subgroup]) for i in range(_spc_nsg)]
_spc_grand_cl = float(np.mean(_spc_means))
_spc_rbar = float(np.mean(_spc_ranges))
# A2[5] = 0.577 from textbook
_spc_a2 = 0.577
_spc_ucl = _spc_grand_cl + _spc_a2 * _spc_rbar
_spc_lcl = _spc_grand_cl - _spc_a2 * _spc_rbar
spc = {
    'xbarChart_basic': {'data': _spc_data, 'subgroupSize': _spc_subgroup,
        'centerline': _spc_grand_cl, 'ucl': _spc_ucl, 'lcl': _spc_lcl, 'rBar': _spc_rbar},
}
ref['spc'] = spc
```

## Key Design Decisions

1. **No new pip dependencies** — all oracles use already-imported scipy/numpy/sklearn/statsmodels.
2. **Formula verification, not model matching** — for modules like `demo.js` (life table) we compute the textbook formula in Python rather than using an external library, ensuring an independent re-implementation.
3. **Precision: 4 decimal places for deterministic formulas, 2 for statistical estimates** — matches Phase 1 conventions.
4. **No fixture dump changes needed** — all oracle data is defined inline in `gen-reference.py` (none of these modules use the shared fixture pipeline).
5. **HARD modules (bandit, deepLearning, fda, nlp, sensitivity) are OUT OF SCOPE** for this phase. They require property-based/invariant tests rather than numeric oracles, or new pip dependencies (SALib, gensim).

## Module-Specific Notes

- **spc.js**: The A2/D3/D4 constants are hardcoded lookup tables in the JS. The oracle verifies the CL/UCL/LCL computed from the same data using the textbook formula. No need to verify the constants themselves (they're textbook values).
- **privacy.js**: The Laplace mechanism and ε-budget are deterministic formulas. Verify ε-sum not exceeded and k/l properties hold for test data.
- **text.js**: TF-IDF in the JS uses its own tokenizer. The sklearn oracle uses the same documents as raw strings, so sklearn's built-in tokenizer handles preprocessing. TF-IDF weights may differ slightly due to tokenizer/IDF smoothing — use precision 2.
- **raMonitor.js**: CUSUM/VLAD decision rules are deterministic given data and thresholds. Verify alarm signals match numpy implementation.
- **pointProcess.js**: Poisson process inter-arrival times ~ Exponential(λ). Verify λ estimate and intensity function values match scipy.stats.

## Risk Mitigation

- **TF-IDF mismatch**: sklearn's TfidfVectorizer uses `smooth_idf=True` by default vs. the JS `idf[t] = log(nDocs / (1 + df[t]))` which is a different IDF formula. Mitigation: compute IDF manually in Python to match the JS formula exactly.
- **Life table rounding**: The JS rounds intermediate values (qx, lx) which propagates. The Python oracle must match the same rounding.
- **pro.js MID**: The anchor-based method depends on `anchorMean ± 0.5*anchorSD` split. Use the same exact data from the test fixture.
