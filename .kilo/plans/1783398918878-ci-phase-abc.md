### Common Fix Patterns

**TS2339 — Property on vague type:**
```js
// Before: @param {object} data
// After:  @param {number[]} data
export function mean(data) {
  return avg(data)  // was: TS2339: 'avg' expects number[], got object
}

// Before: @param {object} options
// After:  @param {{alpha?: number, beta?: number}} options
export function test(data, options = {}) {
  const { alpha = 0.05 } = options  // TS2339: Property 'alpha' doesn't exist on 'object'
}
```

**TS2362/TS2363 — Arithmetic on non-number:**
```js
// Before: @param {*} x
// After:  @param {number} x
export function square(x) {
  return x * x  // TS2362/TS2363: arithmetic on type 'any'
}
```

**TS1016 — Required after optional:**
```js
// Before: export function foo(a, b = 1, c) { ... }
// After:  export function foo(a, b = 1, c = 0) { ... }
//    or:  export function foo(a, c, b = 1) { ... }
```

## Phase C — Lint Cleanup (366 → 0 warnings)

### Goal
Fix all 366 `no-unused-vars` warnings. After fixing, change severity from `'warn'` back to `'error'` in eslint config.

### Fix Categories

| Category | Fix | Example |
|----------|-----|---------|
| Unused import | Remove from `import { ... }` statement. Clean up trailing commas. If last import, remove line. | `import { avg, corr, _fmtP }` → remove `_fmtP` → `import { avg, corr }` |
| Unused function param | Prefix with `_` | `function foo(a, b, c)` with c unused → `function foo(a, b, _c)` |
| Unused local var (defined) | Prefix with `_` | `const x = compute()` → `const _x = compute()` |
| Unused local var (assigned) | Prefix with `_` | `x = compute()` at assignment → `_x = compute()` |

### Key Rules
- **Never remove** a computed variable — it may have side effects (array pushes, mutation). Only prefix.
- **Never remove** a function parameter — it changes the function's arity and could break callers using spread or positional args. Only prefix.
- For **imports**, removal is safe — eslint guarantees the import is never referenced anywhere in the module.
- Use `^_` prefix pattern — the eslint config already allows `_variablename`.

### Process
1. Parse eslint JSON output (`eslint src/ --format json`) to get file + line + variable name + error type for each of the 366 warnings
2. Fix file by file, from most warnings to least (similar order as phase B, since files with many type errors typically have many lint warnings too)
3. After each file: `pnpm --filter statlab lint` to confirm warning count decreases
4. Run `pnpm --filter statlab test` after every 10 files to catch accidental breakage
5. When all 366 warnings reach 0:
   - Change `'no-unused-vars': ['warn', ...]` → `'no-unused-vars': ['error', ...]` in `packages/statlab/eslint.config.js`
6. Commit changes

### Validation

## Risks

- **Phase B**: JSDoc refinement may accidentally narrow a type that's legitimately broader (e.g., a function that genuinely accepts both `number` and `number[]`). Revert if any test breaks.
- **Phase C**: Prefixing a variable with `_` that's used elsewhere in the same expression (e.g., template literal `${x}` where `x` is the unused var) will break. Check surrounding lines before prefixing.
- **Phase C**: Removing an import and failing to clean up the trailing comma will produce a syntax error. Test each file after editing.
- **Git conflicts**: Phases B and C are sequential, so no intra-phase conflicts. But both modify files from the same branch; each phase's commits build on the previous.
